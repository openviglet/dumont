# Shipped Ledger

## Block A — Source configuration moves between instances

- ✅ **DU1** **An AEM source JSON exported from the console has no id, so the first-start import of export/*.json fails on it** — The first-start import now accepts a source with no id, minting one and skipping a name that exists, and the console export writes the id so a re-import is idempotent.
- ✅ **DU2** **AEM sources cannot be exported or imported as a set through the API, unlike DB and web-crawler sources** — GET /api/v2/aem/source/export returns every AEM source as a zip holding export.json, and POST /import takes that zip or a plain .json, like DB and web-crawler.
- ✅ **DU3** **The console accepts a source name containing spaces, and that source then fails to index** — The AEM source form, the AEM wizard and the DB and assets source forms refuse a name with whitespace before saving, with a message saying the name is part of the URLs.
- ✅ **DU4** **The source lists offer no export-all or import action, so the export endpoints are reachable only by API calls** — The AEM, DB, web-crawler and assets source lists offer Export all (ZIP) and Import ZIP, the import also on the empty list, calling each plugin's export and import endpoints.
- ✅ **DU5** **npm run lint in dumont-react exits before checking a file, because the tree has no ESLint flat config** — npm run lint is a working gate: the flat config is in, and no-explicit-any, purity and refs hold everywhere; the two react-hooks lists left are DU8.
- ✅ **DU6** **The source APIs and both imports save a source name containing spaces, which then fails to index** — The AEM, DB and assets source APIs answer 400 on a name with whitespace, their imports skip such a source with a log line, and the samples use slug names.
- ✅ **DU7** **Every dumont-react build fails to generate the Module Federation type declarations, yet exits 0** — The build generates the federated type declarations into mf-types from tsconfig.app.json, and a generator error now fails the build instead of exiting 0.
- ✅ **DU8** **Two react-hooks rules are switched off in 31 named console files, so new violations there pass the lint gate** — react-hooks/set-state-in-effect is an error across the console too: state an effect used to correct is derived at render, and eslint.config.js turns no rule off by file.
- ✅ **DU9** **A source import can only add, so a file cannot overwrite the sources an instance already has** — Source imports take mode=replace: existing sources deleted and the file's created in one transaction, invalid names refused (design superseded: ids regenerate; history is keyed by name).
- ✅ **DU10** **No source API can say what an import would create, overwrite or remove before it writes** — A replace import with dryRun=true answers the create, overwrite, remove and invalid names from the same matching code, writing nothing.
- ✅ **DU11** **The DB, web-crawler and assets imports and the console's Import ZIP refuse a plain JSON file** — The DB, web-crawler and assets imports read a plain export.json like the AEM one, and the source lists' import accepts .zip or .json.
- ✅ **DU12** **The source lists cannot replace every source from a JSON file, nor warn that everything will be overwritten** — Each source list offers Import and replace all: a dry run fills a dialog warning everything is overwritten, listing deletions; invalid names block the confirm.
- ✅ **DU13** **The AEM plugin's JPA integration test cannot start, and the build never runs it** — DumAemSourceApiIT starts from a test configuration and runs in every AEM build, now including a replace case proven against H2.
- ✅ **DU14** **No source import updates the sources a file names while keeping the others** — The AEM, DB, web-crawler and assets imports take mode=merge: sources the file names are recreated from it, new ones created, the rest kept, with a dry run that removes nothing.
- ✅ **DU15** **The server imports silently ignore the JSON a source page exports for a single source** — Imports tell zip from JSON by content, wrap a single source object as one source, and refuse other shapes with 400 naming the accepted ones.
- ✅ **DU16** **The source lists offer three overlapping imports, and none says which existing sources a file will replace** — Each source list has one Import: it merges at once, or lists the sources it replaces and offers to delete the rest (design superseded: it previews by replace dry run, which names removals).
- ✅ **DU17** **An imported source that omits localePaths, attributes or models fails the whole import with a NullPointerException** — AEM and web-crawler source files that leave out their lists import with those lists empty instead of failing on a NullPointerException.
